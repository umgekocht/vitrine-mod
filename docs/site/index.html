Klasse A · sofort aktiv

Inhalte, die als Daten vorliegen

  • Texturen, Sounds und Sprachdateien
  • Themes für die Vitrine-Oberfläche
  • HUD-Module, in JSON beschrieben
  • Shader-Presets, Cosmetics, Einstellungsprofile

Wird über einen eigenen Resource-Pack-Anbieter eingehängt und mit einem Ressourcen-Reload übernommen. Führt keinen Programmcode aus — dafür gibt es keinen Pfad, nicht bloß keine Erlaubnis.

Klasse B · Neustart nötig

Klassische Java-Mods

  • Wird geprüft und nach mods/ gelegt
  • Karte trägt ein sichtbares Band „Neustart nötig“
  • Standardmäßig ausgeblendet, per Schalter zuschaltbar
  • Rücknahme jederzeit, solange nicht neu gestartet wurde

Kommt später als Klasse A und bleibt optional. Wer sie nie einschaltet, sieht sie nie.

Paketformat

Ein .vpkg ist ein ZIP, das ehrlich sagt, was es anfasst

Vitrine packt nichts aus. Es liest direkt im Archiv — kein Müll auf der Platte, kein Halbzustand, wenn ein Download abbricht.

vitrine.json          Manifest, Pflicht
assets/…              Texturen, Sounds, Sprachen
theme.json            Farb- und Maß-Tokens
hud/*.json            Widgets, deklarativ
preview/card.png      Kachelbild 512×288
LICENSE               Pflicht

// im Manifest, im Klartext:
"capabilities": [
  "resources",
  "theme",
  "hud"
]

Was vor der Installation passiert

  • SHA-256 und ed25519-Signatur werden geprüft — vor dem Anwenden, nicht danach
  • Jeder Archiveintrag muss innerhalb des Pakets landen: .., absolute Pfade und Symlinks fliegen raus
  • Deckel auf entpackte Größe, Kompressionsverhältnis und Eintragszahl
  • Bildmaße kommen aus dem PNG-Header, bevor irgendetwas dekodiert wird
  • Du siehst im Klartext, was das Paket darf, und kannst genauso leicht ablehnen wie zustimmen

Fähigkeiten sind eine Whitelist. Was nicht im Manifest steht, existiert für das Paket nicht.

Katalog

Kein Server, keine laufenden Kosten

Der Katalog ist eine Datei auf GitHub Pages, die Pakete liegen als Release-Anhänge im Repo ihrer Autoren. Der Client lädt nur über HTTPS und nur von festgelegten Hosts. Ohne Netz öffnet der Store trotzdem und zeigt den letzten Stand.

  1. Du Paket im Designer bauenTheme-Editor, Texturzuordnung, HUD-Raster, Manifest mit Live-Prüfung. Am Ende steht ein .vpkg.
  2. Du git tag v1.0.0 && git push --tagsDas ist der letzte Handgriff. Ab hier fasst du nichts mehr an.
  3. Automatisch Action im eigenen RepoBaut das Archiv, signiert es, hängt es ans Release und öffnet einen Pull Request am Katalog.
  4. Automatisch Prüfung im KatalogSchema, Lizenz, Größendeckel, Archivsicherheit, Signatur. Grün heißt Merge, rot heißt Rückmeldung im Pull Request.
  5. Automatisch Index neu gebautWenige Minuten später taucht das Paket bei allen im Spiel auf.

Projekt

Offen entwickelt, Apache-2.0

Vitrine entsteht gerade. Quellcode, Katalog und die Vorlage für Paket-Autoren landen alle auf GitHub — hier steht, was davon schon existiert, damit niemand auf einen Link klickt, der ins Leere führt.

Das Fundament steht: Fabric-Projekt, Konfiguration, Oberflächengrafiken, grüner Build. Als Nächstes kommen Paketformat und Hot-Apply. Sobald ein Release existiert, steht der Link hier — nicht vorher.

Profil ansehen

Maßstab für „fertig“

Wer den Jar herunterlädt und in mods/ legt, hat alle Funktionen: Store öffnet, Katalog lädt, Pakete installieren sich, alles ohne Neustart. Ohne Konto, ohne Token, ohne Konfiguration. Was nur auf einem Rechner läuft, gilt nicht als fertig.
